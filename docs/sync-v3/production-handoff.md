## Operator commands

Use the owner-only TLS connection for migration operations. Use no owner, legacy or API database URL in the v3 process. Supply `SYNC_V3_WORKER_PASSWORD`, `SYNC_V3_PROJECTOR_PASSWORD` and `SYNC_V3_PUBLISHER_PASSWORD` via Render service secrets. `SYNC_V3_SESSION_HOST` accepts the pinned direct host or a Supabase shared session host on 5432. Runtime identity checks require the dedicated SQL role and project database. The control administrator, acquisition worker, projector and publisher have separate responsibilities.

For the provider drain, set `OLD_OWNER_DIRECT`, `OLD_OWNER_SESSION` and `OLD_OWNER_TRANSACTION` in an operator-only process. Set `SYNC_V3_DEDICATED_POOL` to `enabled` or `disabled` after confirmation. Supply `OLD_OWNER_DEDICATED` if enabled. For each endpoint set the corresponding `NEW_OWNER_<ENDPOINT>_FILE` path to an owner-readable, mode-0600 secret file outside the repo. Populate those files through the secret manager after rotation. Start `python -m scripts.verify_owner_pool_drain --revision "$REV" --output pool-drain.json` and keep it connected until the provider drain finishes. Keep only per-endpoint results and clean up the private files. A failed fresh control or ambiguous network error blocks activation.

```sh
BASE=https://baseballos-api.onrender.com
curl --fail --silent "$BASE/api/bullpen/team-states" | jq '.publication_authority | {snapshot_id,sync_run_id}'
python -m scripts.verify_public_sync_edition --base-url "$BASE" --snapshot "$OLD_SNAPSHOT" --sync "$OLD_SYNC" --capture-legacy-predecessor > legacy.json
python -m sync_v3.handoff_admin activate --revision "$REV" --receipt legacy.json --pool-drain pool-drain.json
# Run on the configured v3 cron; independent verification runs outside it.
python -m sync_v3.production cycle
python -m scripts.verify_public_sync_edition --base-url "$BASE" --snapshot "$NEW_SNAPSHOT" --sync "$NEW_SYNC" --binding reviewed-generation.json
```

The capture uses the read-only `SYNC_V3_PREFLIGHT_DATABASE_URL`. Export the exact stored `v3_source_generation` bound to the new snapshot from the reviewed publication as `reviewed-generation.json`; match its digest to the independent source review in the primary receipt. Use secret-safe identity inspection on the replacement bindings. Test denied operations in rolled-back transactions with the actual old paths; check for permission rejection and preserve the response code without logging a token. A missing token or an empty table is insufficient.

```sh
python -m sync_v3.handoff_admin begin-rollback --revision "$REV" --receipt legacy.json
# Controlled publisher process with its own password and NO owner URL
SYNC_V3_ROLLBACK_SNAPSHOT="$NEW_SNAPSHOT" SYNC_V3_ROLLBACK_GENERATION="$NEW_GENERATION" python -m sync_v3.production rollback
python -m scripts.verify_public_sync_edition --base-url "$BASE" --snapshot "$OLD_SNAPSHOT" --sync "$OLD_SYNC" --expect-public-sha256 "$(jq -r .public_edition_sha256 legacy.json)"
# After the publisher is NOLOGIN and its sessions have drained, on the migration runner
python -m sync_v3.handoff_admin release-legacy --revision "$REV" --receipt legacy.json
```

If activation fails before commit, verify the original selector and public fingerprint, then re-enable only the previously authorized scoped legacy role and its required schedules. A public mismatch after rollback holds all schedulers and requires investigation. The exact public fingerprint includes a dated Tonight row. The rollback command checks the current baseball date before changing the selector. A delayed cutover or recovery outside the agreed window requires a current-date recovery receipt; the historical root alone cannot certify today's Tonight route. Publication rollback restores the verified selector and sync-run links. It preserves the acquired evidence and canonical history.
